Ground Rules

⚙ How We Work

▸Prompt each module using its code — P1M1, P1M2, P2M5, etc.
▸You write every query. I never give the answer first. You attempt, paste, I review.
▸Exit gate is mandatory — answer "when NOT to use" before I open the next module.
▸No skipping. If a module runs over, cut buffer — not module depth.
▸Day 3 ends with a timed mock interview. No hints. Treat it as the real thing.

🗣 How to Think Out Loud

▸Before writing, state the grain: "One row per student? Per dept? Per semester?"
▸State the join type and why: "LEFT JOIN because I want to keep unplaced students."
▸Name the construct before using it: "This needs a window function, not GROUP BY, because I need row-level detail alongside the rank."
▸Check for NULL traps before submitting: which columns could be NULL and does my query handle them?

Query Review Protocol

✅
Correct logic

Confirmed, expected output shown, and we move directly to the next question.

⚠️
Right idea, one bug

I point to the exact line and describe the category of error. You find and fix it — I don't rewrite it for you.

❌
Wrong approach

I ask a diagnostic question that points you toward the right construct. You rethink and rewrite from scratch.
