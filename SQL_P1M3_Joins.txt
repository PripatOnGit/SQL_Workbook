Master Guide: SQL Joins & Relational Data (P1M3)1. Core Mental ModelA JOIN in SQL is fundamentally a filtered cross product.When you join two tables, the engine conceptually pairs every row from Table A with every row from Table B ($M \times N$ Cartesian product). The ON clause acts as a filter during join processing to retain only valid row pairs.┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. ANCHOR TABLE: Which table's rows must I NEVER lose?                     │
│    └─► Determines LEFT JOIN vs INNER JOIN.                                  │
│                                                                             │
│ 2. FAN-OUT RISK: Could the right side fan-out my rows before aggregating?  │
│    └─► If yes, aggregate in a CTE/subquery FIRST.                           │
│                                                                             │
│ 3. FILTER PLACEMENT: Am I filtering the right-side table in WHERE?          │
│    └─► Move optional filters to ON clause to avoid accidental INNER JOIN.   │
│                                                                             │
│ 4. NECESSITY CHECK: Do I actually need columns from both tables?            │
│    └─► If filtering only, consider EXISTS or IN instead of a JOIN.          │
└─────────────────────────────────────────────────────────────────────────────┘

Interview Traps & Core Concepts⚠️ Gotcha 1: Filter in ON vs. WHERE for Outer JoinsON Clause: Evaluates during table matching. Unmatched anchor rows are kept with NULL on the right side.WHERE Clause: Evaluates after join result generation. NULL evaluations drop those rows entirely.SQL-- ❌ WRONG: Converts LEFT JOIN to INNER JOIN
SELECT s.name, p.company 
FROM students s 
LEFT JOIN placements p ON s.student_id = p.student_id 
WHERE p.offer_date >= '2025-01-01';

-- ✅ CORRECT: Preserves unplaced students with NULLs
SELECT s.name, p.company 
FROM students s 
LEFT JOIN placements p ON s.student_id = p.student_id 
  AND p.offer_date >= '2025-01-01';
⚠️ Gotcha 2: Join Fan-Out Inflates AggregatesJoining a $1 \rightarrow N$ relationship duplicates rows on the "1" side before aggregations (SUM, AVG, COUNT) run.SQL-- ❌ WRONG: Inflates s.scholarship by number of enrollments
SELECT s.student_id, SUM(s.scholarship)
FROM students s
JOIN enrollments e ON s.student_id = e.student_id
GROUP BY s.student_id;

-- ✅ CORRECT: Aggregate the "many" side before joining
WITH enrollment_counts AS (
    SELECT student_id, COUNT(course_id) AS total_courses
    FROM enrollments
    GROUP BY student_id
)
SELECT s.student_id, s.scholarship, COALESCE(ec.total_courses, 0) AS total_courses
FROM students s
LEFT JOIN enrollment_counts ec ON s.student_id = ec.student_id;
4. Key Reusable PatternsPattern A: Anti-JoinFinds records in Table A that have no matching record in Table B.SQLSELECT s.name, s.dept_id, s.gpa
FROM students s
LEFT JOIN placements p ON s.student_id = p.student_id
WHERE p.student_id IS NULL;
Pattern B: Safe Default Handlers (COALESCE)Converts missing values from LEFT JOIN operations into structured default values.SQLSELECT 
    s.name,
    COALESCE(p.company, 'Not Placed') AS company,
    COALESCE(p.ctc, 0) AS ctc
FROM students s
LEFT JOIN placements p ON s.student_id = p.student_id;
Pattern C: Hierarchical Self-JoinLinks child rows to parent rows within the same entity table.SQLSELECT 
    c1.course_name, 
    COALESCE(c2.course_name, 'None') AS prerequisite_course_name
FROM courses c1 
LEFT JOIN courses c2 ON c1.prereq_course_id = c2.course_id;
5. Complete Practice Log (Q1 – Q5)Q1 · Easy — INNER JOINPrompt: Show each student's name and their dept_name. Only include students belonging to a valid department. Order by dept_name, then name.Grain: 1 row per valid student-department pair.Key Concept: INNER JOIN filters out invalid/unmatched foreign key references.SQLSELECT 
    s.name, 
    d.dept_name
FROM students s 
INNER JOIN departments d ON s.dept_id = d.dept_id
ORDER BY d.dept_name, s.name;
Q2 · Easy — LEFT JOIN + COALESCEPrompt: Show all students with placement company and ctc. Unplaced students show 'Not Placed' and 0. Order by ctc descending.Grain: 1 row per student.Key Concept: Preserve anchor table records and format output columns using COALESCE.SQLSELECT 
    s.name, 
    COALESCE(p.company, 'Not Placed') AS company,
    COALESCE(p.ctc, 0) AS ctc
FROM students s 
LEFT JOIN placements p ON s.student_id = p.student_id
ORDER BY ctc DESC;
Q3 · Medium — Anti-JoinPrompt: Find every student who has never been placed. Show name, dept_id, and gpa. Order by gpa descending.Grain: 1 row per unplaced student.Key Concept: Combine LEFT JOIN with WHERE right_table_key IS NULL.SQLSELECT 
    s.name, 
    s.dept_id, 
    s.gpa
FROM students s 
LEFT JOIN placements p ON s.student_id = p.student_id
WHERE p.student_id IS NULL
ORDER BY s.gpa DESC;
Q4 · Medium — ON vs. WHERE PlacementPrompt: Show all students and their placement company, only including placements made in 2025 or later. Preserve unplaced/pre-2025 students with NULL.Grain: 1 row per student.Key Concept: Right-side filter must reside in ON to prevent dropping anchor rows.SQLSELECT 
    s.name, 
    p.company
FROM students s 
LEFT JOIN placements p ON s.student_id = p.student_id
  AND p.offer_date >= '2025-01-01';
Q5 · Hard — Hierarchical Self-JoinPrompt: Show each course's course_name alongside its prerequisite course_name. Display 'None' if no prerequisite exists. Include all 8 courses.Grain: 1 row per course.Key Concept: Self-join c1.prereq_course_id = c2.course_id using LEFT JOIN to keep root nodes.SQLSELECT 
    c1.course_name, 
    COALESCE(c2.course_name, 'None') AS prerequisite_course_name
FROM courses c1 
LEFT JOIN courses c2 ON c1.prereq_course_id = c2.course_id;
