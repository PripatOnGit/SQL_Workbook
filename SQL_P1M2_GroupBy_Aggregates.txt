Executive Summary & Mental ModelThe Core GoalGrouping and aggregation allow you to collapse multiple rows of individual records into a single summary row per category/group.SQL Execution OrderUnderstanding when GROUP BY and HAVING execute is essential for writing bug-free queries:$$\text{FROM} \longrightarrow \text{WHERE} \longrightarrow \text{GROUP BY} \longrightarrow \text{HAVING} \longrightarrow \text{SELECT} \longrightarrow \text{ORDER BY} \longrightarrow \text{LIMIT}$$WHERE: Filters individual rows before grouping occurs.GROUP BY: Groups the filtered rows based on unique values in specified columns.HAVING: Filters entire groups after aggregations are calculated.⚠️ Golden Rule: Any column in your SELECT clause that is not wrapped in an aggregate function MUST be listed in the GROUP BY clause. Otherwise, SQL throws a non-aggregated column error (or returns arbitrary non-deterministic values in older MySQL modes).2. Essential Guardrails & FunctionsA. Protecting Against Division by Zero: NULLIF(a, b)When calculating ratios, percentages, or averages manually (e.g., total amount divided by count of recipients), a count of 0 will crash your query with a Division by zero error.Syntax: NULLIF(expression1, expression2)Behavior: Returns NULL if expression1 == expression2; otherwise returns expression1.Pattern:SQL-- Safe Ratio Calculation:
SUM(scholarship_amount) / NULLIF(COUNT(scholarship_id), 0)
If count is 3: Evaluates to SUM / 3 $\rightarrow$ returns valid average.If count is 0: NULLIF(0, 0) returns NULL $\rightarrow$ SUM / NULL evaluates safely to NULL (no crash!).B. Formatting Results: ROUND(val, decimals)Used to clean up floating-point aggregate outputs (like averages or percentages).SQLROUND(AVG(gpa), 2)  -- Rounds average GPA to 2 decimal places
4. WHERE vs. HAVING (Interview Trap)This is one of the most common interview questions:SQL-- ❌ WRONG: Aggregates inside WHERE clause
SELECT dept_id, AVG(gpa)
FROM students
WHERE AVG(gpa) > 3.0   -- Error! WHERE cannot process aggregates.
GROUP BY dept_id;

-- ✅ CORRECT: Using WHERE for row filtering & HAVING for group filtering
SELECT dept_id, ROUND(AVG(gpa), 2) AS avg_gpa
FROM students
WHERE status = 'active'     -- 1. Filter rows first (Active students only)
GROUP BY dept_id            -- 2. Group active students by department
HAVING AVG(gpa) > 3.0       -- 3. Filter groups (Departments with avg GPA > 3.0)
ORDER BY avg_gpa DESC;
5. Cheat Sheet / Quick Syntax Patterns1. Simple Group AggregationSQLSELECT dept_id, COUNT(student_id) AS student_count
FROM students
GROUP BY dept_id
ORDER BY student_count DESC;
2. Multi-Column GroupingSQLSELECT dept_id, status, COUNT(*) AS student_count
FROM students
GROUP BY dept_id, status;
3. Combining Conditional Aggregations with CASE WHENSQLSELECT 
    dept_id,
    COUNT(student_id) AS total_students,
    COUNT(CASE WHEN status = 'active' THEN 1 END) AS active_students,
    SUM(CASE WHEN status = 'active' THEN 1 ELSE 0 END) AS active_sum
FROM students
GROUP BY dept_id;
