SQL Grouping & Aggregations: Ultimate Reference Guide
1. Executive Summary & Mental Model
The Core Goal
Grouping and aggregation allow you to collapse multiple rows of individual records into a single summary row per category or group.

SQL Execution Order
Understanding when GROUP BY and HAVING execute is essential for writing bug-free queries:

FROM⟶WHERE⟶GROUP BY⟶HAVING⟶SELECT⟶ORDER BY⟶LIMIT
WHERE: Filters individual rows before grouping occurs.

GROUP BY: Groups the filtered rows based on unique values in specified columns.

HAVING: Filters entire groups after aggregations are calculated.

⚠️ Golden Rule: Any column in your SELECT clause that is not wrapped in an aggregate function MUST be listed in the GROUP BY clause. Otherwise, SQL throws a non-aggregated column error (or returns non-deterministic values in older MySQL modes).

3. Essential Guardrails & Helper Functions
A. Protecting Against Division by Zero: NULLIF(a, b)
When calculating ratios, percentages, or averages manually (e.g., total amount divided by count of recipients), a count of 0 will crash your query with a Division by zero error.

Syntax: NULLIF(expression1, expression2)

Behavior: Returns NULL if expression1 == expression2; otherwise returns expression1.

Pattern:

SQL
-- Safe Ratio Calculation:
SUM(scholarship_amount) / NULLIF(COUNT(scholarship_id), 0)
If count is 3: Evaluates to SUM / 3 → returns valid average.

If count is 0: NULLIF(0, 0) returns NULL → SUM / NULL evaluates safely to NULL (prevents query crash).

B. Formatting Results: ROUND(val, decimals)
Used to clean up floating-point aggregate outputs (like averages or percentages).

SQL
ROUND(AVG(gpa), 2)  -- Rounds average GPA to 2 decimal places
4. Problem-Solving Framework (5 Steps)
When tackling any SQL grouping/aggregation question, follow this step-by-step approach:

Identify the Grain: What does one row in the final output represent? (e.g., "One row per department" → GROUP BY dept_id).

Filter Individual Rows (WHERE): Ask: "Do I need to filter individual records before grouping?" (e.g., status = 'active').

Group the Data (GROUP BY): Put all non-aggregated columns from your SELECT statement into GROUP BY.

Filter Aggregated Groups (HAVING): Ask: "Am I filtering based on a calculation/summary?" (e.g., AVG(gpa) > 3.0).

Format & Safeguard (ROUND, NULLIF, ORDER BY): Clean up decimal places, protect against division by zero, and sort the final dataset.

5. WHERE vs. HAVING (Interview Pattern)
SQL
-- ❌ WRONG: Aggregates inside WHERE clause
SELECT dept_id, AVG(gpa)
FROM students
WHERE AVG(gpa) > 3.0   -- Error! WHERE cannot process aggregates.
GROUP BY dept_id;

-- ✅ CORRECT: Using WHERE for row filtering & HAVING for group filtering
SELECT dept_id, ROUND(AVG(gpa), 2) AS avg_gpa
FROM students
WHERE status = 'active'     -- 1. Filter rows first (Active students only)
GROUP BY dept_id            -- 2. Group active students by department
HAVING AVG(gpa) > 3.0       -- 3. Filter groups (Departments with avg GPA > 3.0)
ORDER BY avg_gpa DESC;
6. Complete Q&A Walkthrough Reference
Q1: Department Student Count
Question: Count total students per department, ordered from highest to lowest.

Grain: One row per dept_id.

Approach: No row-level filtering needed. Group by dept_id and use COUNT(student_id).

Query:

SQL
SELECT dept_id, COUNT(student_id) AS student_count
FROM students
GROUP BY dept_id
ORDER BY student_count DESC;
Q2: Active Students Average GPA
Question: Calculate average GPA per department for active students only, rounded to 2 decimal places. Order by avg_gpa descending.

Grain: One row per dept_id.

Approach: status = 'active' is a row-level condition → goes in WHERE. Round the AVG(gpa).

Query:

SQL
SELECT dept_id, ROUND(AVG(gpa), 2) AS avg_gpa
FROM students
WHERE status = 'active'
GROUP BY dept_id
ORDER BY avg_gpa DESC;
Q3: Department Scholarship Ratio / Division-by-Zero Safety
Question: Calculate average scholarship amount per scholarship recipient in each department.

Grain: One row per dept_id.

Trap: Departments with 0 scholarship recipients will cause a Division by zero error if dividing directly.

Approach: Wrap COUNT(scholarship) inside NULLIF(..., 0) so zero counts safely evaluate to NULL.

Query:

SQL
SELECT 
    dept_id,
    SUM(scholarship_amount) / NULLIF(COUNT(scholarship_id), 0) AS avg_scholarship_per_recipient
FROM students
GROUP BY dept_id;
Q4: High-Performing Departments (HAVING Clause)
Question: Find departments where the overall average GPA is strictly greater than 3.2.

Grain: One row per dept_id.

Trap: You cannot put AVG(gpa) > 3.2 in WHERE because WHERE evaluates before groups are created.

Approach: Place the aggregate filter in the HAVING clause after GROUP BY.

Query:

SQL
SELECT dept_id, ROUND(AVG(gpa), 2) AS avg_gpa
FROM students
GROUP BY dept_id
HAVING AVG(gpa) > 3.2;
